# 主题 / 换肤功能调研

> 调研日期：2026-07-27
> 范围：悬浮时钟是否应提供主题（换肤）能力、以何种形式提供、实施边界与验收标准。依据为本仓库只读检查、Tauri / WebView2 官方文档与已公开的 Tauri Issue。
>
> **2026-07-30 更新**：主题功能已按本文边界完成。最终提供琥珀暗、晨雾浅、墨玉黑、樱粉四套预设；跟随系统明暗暂未实现。

## 需求

当前应用只有一套固定配色。需求是让用户能在多套界面外观之间切换，并记住选择。

本次调研包含：

- 主题的表达方式（CSS 变量 token 化）与切换机制；
- 主题应覆盖的样式维度边界（颜色、字体、圆角、明暗声明）；
- 切换入口在固定尺寸窗口下的可行位置；
- 偏好持久化与「跟随系统明暗」；
- 与现有 CSP、WebView2 兼容性、测试和 Mini 模式的相互影响。

本次调研不包含：

- 不实现任何主题功能；
- 不改动 Tauri / Rust 后端、桥接层、托盘、置顶或窗口尺寸规则；
- 不增加依赖、不引入 CSS 预处理器、不放宽现有 CSP；
- 不改变时间源、校准、倒计时逻辑或 `localStorage` 现有键的数据格式。

## 结论先行

1. **推荐做「CSS 变量语义化 + 预设主题 + 可选跟随系统明暗」**，纯前端实现，不动 Rust 侧，不加依赖，不放宽 CSP。
2. **前置重构不可绕开**：当前样式中颜色全部为硬编码字面量，必须先抽成语义 token 才谈得上换肤。这一步无可见变化、可独立验证，应作为阶段一单独完成。
3. **token 必须包含字体族与圆角，不能只有颜色。**只换色号的预设之间差异过小，用户难以感知「换了主题」；字体与圆角是决定整体观感的主要变量，而纳入 token 的成本接近于零。
4. **标题文案、emoji 与图标形状不纳入主题系统。**前者属品牌层，如确有需求应作为独立的「自定义标题」设置项；后者为内联 SVG 路径，改造成本高、收益低。
5. **不做用户自带主题文件（外部 JSON / CSS）。**需要开放文件系统能力并放宽 CSP，对本项目体量属于过度设计；改为在 README 公布 CSS 变量清单，让有能力的用户自行调整。

## 主题应覆盖的维度

主题系统的边界决定了它是否值得做。逐维度结论如下：

| 维度 | 是否纳入 | 理由 |
| --- | --- | --- |
| 配色 | 是 | 主题的基本内容 |
| 字体族 | 是 | 决定整体观感；仅 `:root` 一处声明，纳入成本接近零 |
| 圆角半径 | 是 | 同上；当前 4 种取值可收敛为 2–3 个 token |
| `color-scheme` | 是 | 不同步会导致浅色主题下出现深色原生控件 |
| 阴影强度 | 是 | 已随颜色 token 一并派生，无额外成本 |
| 标题文案 / emoji | 否 | 属品牌层，与主题解耦；如需开放应作为独立设置项 |
| 图标形状 | 否 | 内联 SVG 路径，需改 HTML 结构，成本高收益低 |
| 布局与尺寸 | 否 | 窗口固定 392×392，布局已满，无调整余量 |

## 推荐方案

### 阶段一：token 重构（无可见变化）

把 `styles.css` 的颜色、字体、圆角抽为 `:root` 语义变量。透明度变体不逐个定义，用 `color-mix()` 从基色派生：

```css
:root {
  color-scheme: var(--color-scheme);
  --color-scheme: dark;
  --font-family: "Segoe UI", "Microsoft YaHei UI", sans-serif;
  --radius-shell: 8px;
  --radius-control: 6px;
  --color-fg: #f6f4ef;
  --color-accent: #f2b84b;
  --color-on-accent: #16130c;
  --color-surface-raised: #1b2023;
  --color-critical: #ff6f61;
  --color-success: rgb(76, 210, 137);
  /* 派生示例，替代原 rgba(242, 184, 75, 0.18) */
  --color-accent-soft: color-mix(in srgb, var(--color-accent) 18%, transparent);
}
```

建议的 token 分组：前景（主 / 次 / 弱三级）、表面（窗体 / 浮层）、控件（底 / hover）、描边、强调（底 / 文字 / 底上文字）、语义色（警示 / 成功）、阴影、字体、圆角、`color-scheme`。总量控制在 20 个以内。

`color-mix()` 需要 Chromium 111+（2023 年 3 月）。项目使用 Evergreen WebView2，实际能力取决于用户机器的 Runtime 版本；该基线足够保守，但仍应在验收时于真实窗口确认一次。

### 阶段二：主题切换

- `styles.css` 中以 `[data-theme="…"]` 选择器提供各主题的 token 覆盖块；
- `app.js` 在 `bootstrap()` 中读 `localStorage` 并设置 `document.documentElement.dataset.theme`；
- 标准模式右下角增加 `🎨` 按钮，复用现有 `details/summary` 浮层范式向上弹出主题列表；Mini 模式隐藏入口。

最终落地 4 套：**琥珀暗**（默认，即原有外观）、**晨雾浅**、**墨玉黑**（黑底、玉绿强调、直角锐利）、**樱粉**（奶油粉背景、玫粉强调、灰紫文字与中等圆角）。默认值保持琥珀暗，存量用户零感知。

为支持浅色与樱粉主题，原先共用的中性色进一步拆为文字、边框和控件表面三个 RGB token；其他主题通过默认别名保持原有表现。标准模式标题按主题显示英文短名、固定中文主标题和 emoji 标记，标题栏左右各保留两个窗口按钮以维持视觉平衡。

「跟随系统」保留为后续可选项，本次没有实现。若以后增加，可使用 `matchMedia("(prefers-color-scheme: dark)")` 加 `change` 监听，映射到暗 / 浅两套。已知 WebView2 的 `prefers-color-scheme` **始终跟随操作系统主题**、无视 Tauri 配置中强制的 `theme` 字段（[tauri#5802](https://github.com/tauri-apps/tauri/issues/5802)）；本项目未设置该字段，要的恰好就是跟随系统，故该缺陷对本项目无害。

### 对自定义用户的友好措施

token 层设计完成后，在 README 中列出 CSS 变量清单并说明欢迎自定义。相比把所有个性化需求都做进程序，这一做法成本更低，也能覆盖预设之外的长尾需求。

## 明确不采用

- 不做用户自带主题文件（外部 JSON / CSS 加载）：需开放文件系统能力、放宽 CSP，属过度设计；
- 不做自定义强调色取色器：技术上可行（CSSOM `setProperty` 不受 CSP 约束），但首版无需求支撑；
- 不把标题文案、emoji、图标形状纳入主题系统；
- 不为主题改动 Rust 侧、托盘菜单或窗口尺寸规则；
- 不放宽 0.1.3 已加固的 CSP；
- 不引入任何新依赖或 CSS 预处理器；
- 不改变 `localStorage` 现有键的数据格式。

## 风险与注意点

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 视觉回归 | 阶段一是覆盖全文件的机械替换，容易出现个别色值抄错 | 改动前后截图对照抽查标准模式与 Mini 模式 |
| 测试失败 | 4 处测试硬编码了颜色字面量 | 同步改为断言 `var(--…)` |
| 浅色主题可读性 | 窗口 `transparent: true`，悬浮在任意桌面背景上 | 浅色表面不透明度维持 0.96 左右，不可做透 |
| 原生控件明暗 | `datetime-local` 输入框由 `color-scheme` 决定渲染 | 浅色主题必须同步切换该属性，否则出现深色控件浮在浅色面板上 |
| `color-mix` 兼容 | 依赖 Chromium 111+ | 真实窗口验收；如需极端保守可退回逐个定义 alpha 变体 |
| CSP 边界未实测 | 按 CSP 规范，`style-src` 约束 `<style>` 元素与 `style` 属性，不约束 CSSOM 操作 | 该结论不影响本方案（预置主题块无需注入）；若将来做自定义颜色需实测确认一次 |

安全面无变化：无新依赖、无 Rust 改动、无 CSP 放宽。

## 验收清单

1. 阶段一完成后，界面与重构前逐像素一致（标准模式 + Mini 模式对照截图）。
2. `npm test` 全绿；颜色相关断言改为引用式断言。
3. 逐主题检查：标题栏、时间源浮层、模式切换、主数字、快捷目标、状态栏、Mini 三行与右侧操作按钮均无失色或失联。
4. 最后五秒 `.critical` 高亮在每套主题下均可辨识，且脉冲动画不受影响。
5. 浅色主题下 `datetime-local` 输入框及其日历弹层为浅色渲染。
6. 主题偏好重启后保持；`localStorage` 中主题键异常或缺失时回落到默认主题，不报错、不白屏。
7. 切换主题不触发窗口尺寸变化；Mini 模式宽度自适应逻辑不回归。
8. 若后续启用「跟随系统」，手动切换 Windows 明暗主题，确认实时响应。
9. 在真实 Tauri 窗口验收透明背景下各主题的对比度与边缘表现，而非仅看浏览器预览。
