# 数字翻页效果调查

## 调查范围

本文只研究悬浮时钟的数字变化能否加入“翻页 / 翻牌”视觉效果，以及适合当前 Tauri + WebView2 架构的实现边界。

本次调查包含：

- 标准模式时钟与倒计时的主时间数字；
- Mini 模式的主时间数字；
- 整数秒与三位毫秒两种显示精度；
- CSS 3D 动画、Web Animations API（WAAPI）和原生逐位 DOM 的比较；
- 性能、无障碍、减少动态效果和 WebView2 兼容性。

本次调查不包含：

- 不实现任何翻页效果；
- 不改变 Tauri/Rust 后端、桥接层、托盘、置顶或窗口尺寸规则；
- 不增加依赖、不保存动效偏好、不增加设置或快捷键；
- 不把时间源校准、倒计时规则或 Mini 的拖动规则改造成新的行为。

## 结论

数字翻页效果在本项目中技术上可行，推荐以“**稳定的逐位 DOM + CSS 3D 样式 + WAAPI 触发单个位动画**”实现。

但是，翻页必须限于发生变化的时、分、秒数字。三位毫秒（`.mmm`）继续即时更新文字，不做翻页。

原因是当前渲染层每约 `16ms` 执行一次渲染。三位毫秒显示下，毫秒数字会约每秒变动 60 次；若每次变化都做约 `140–180ms` 的翻页，前一个动画尚未结束就会被下一次更新打断，视觉会变为持续抖动、重叠翻转，也会额外创建大量动画对象。

推荐的首版规则：

- 时钟和倒计时：仅变化的时、分、秒位翻页；
- 整数秒模式：每秒变化的数字翻页；
- 三位毫秒模式：秒位在跨秒时翻页，`.mmm` 静态即时替换；
- 冒号和小数点保持不动；
- 首次渲染、切换时间源、重新校时、恢复窗口、显示精度切换和字符串位数变化时，直接显示正确数值，不播放翻页；
- Mini 与标准模式共享数字渲染规则，但 Mini 不新增点击或焦点交互。

## 方案比较

| 方案 | 做法 | 优点 | 主要问题 | 结论 |
| --- | --- | --- | --- | --- |
| 整串 CSS 翻页 | 把完整时间字符串当作一张卡片翻转 | 代码最少 | 秒、毫秒、冒号都会一起翻；三位毫秒模式下几乎持续翻转 | 不采用 |
| 逐位 DOM + CSS animation | 每个数字是一个 span；变化时添加 CSS class，`animationend` 后清理 | 不增加依赖；简单 PoC 容易验证 | 反复添加同一 class 重启动画需要额外处理；异常高频更新更难取消旧动画 | 可行，但不是推荐的正式路径 |
| 逐位 DOM + WAAPI + CSS 3D | DOM 负责固定数字槽位；CSS 提供透视、翻面和背面隐藏；JS 以 `Element.animate()` 驱动每次变化 | 可针对单个位创建、取消和清理动画；不需要强制重排来重启 CSS class；容易回退 | 需要维护每个槽位的当前动画生命周期 | 推荐 |
| 完整机械翻页钟 | 每位拆为上半/下半静态片及两个动态半片 | 最接近实体翻页钟 | 层级、裁切、阴影和半像素问题更多；透明窗口下的视觉调试成本较高 | 不作为首版 |

“逐位 DOM”不是与 CSS 或 WAAPI 互斥的方案，而是后两者正确定位变化数字所需要的基础。推荐组合为：逐位 DOM 提供稳定的槽位，CSS 提供 3D 呈现，WAAPI 管理单次翻页动画。

## 推荐方案与不采用项

### 推荐方案

每个数字使用固定宽度的槽位，例如以 `1ch` 宽度容纳一位等宽数字；冒号和小数点使用静态节点。首次渲染或字符长度变化时创建/重建槽位；其余帧只比较旧字符与新字符，更新发生变化的位置。

数字翻页建议采用轻量的“单数字翻牌”，而不是首版就实现完整上下半页机械时钟：

```text
稳定状态                 变化过程

[ 5 ]                    [旧 5] 向外 rotateX
                            ↓
                         [新 6] 向内 rotateX
```

建议的默认参数：

- 时长：`160ms`；
- 缓动：`ease-in-out`；
- 动画属性：只使用 `transform` 与 `opacity`；
- 3D 上下文：槽位父级提供适量 `perspective`；
- 背面：翻动面的 `backface-visibility: hidden`；
- 数字宽度：继续沿用当前的等宽数字设置；
- 高亮：`.critical` 保持在时间值父级，数字子槽位只处理翻页。

WAAPI 的典型保护逻辑应为：开始新动画前取消该数字槽位尚未完成的旧动画；动画完成后移除旧数字层并清理引用。虽然秒级方案通常不会重叠，但这能让实现对边界变化安全。

### 明确不采用

- 不对 `.mmm` 三位毫秒的每次变化翻页；
- 不对完整字符串、冒号或小数点翻页；
- 不在每个 `render()` 中销毁并重建完整数字 DOM；
- 不用 `width`、`height`、`top`、`left` 或主要依赖 `box-shadow` 变化制作动画；
- 不为所有数字长期添加 `will-change`；
- 不为翻页增加持久化设置、全局快捷键或 Tauri 命令；
- 不将时间源校时产生的跳变伪装成自然的逐秒翻页。

## 具体动画边界

| 场景 | 建议行为 |
| --- | --- |
| `12:34:56.789` → `12:34:56.805` | 只更新 `.mmm`，不翻页 |
| `12:34:56.999` → `12:34:57.000` | 仅秒个位 `6 → 7` 翻页；毫秒直接更新 |
| `12:34:59.999` → `12:35:00.000` | 秒的两位和分钟个位同步翻页 |
| `09:59:59` → `10:00:00` | 所有发生变化的数字同步翻页 |
| 倒计时 `00:01:00` → `00:00:59` | 变化的分钟、秒位同步翻页 |
| 倒计时从 `99:59:59` 到 `100:00:00` 或反向变化 | 字符串长度变化，静态重建槽位；Mini 沿用已有的一次性宽度调整 |
| 切换“显示整秒 / 显示毫秒” | 静态替换或重建数字槽位，不翻页 |
| 初次显示、切换时钟/倒计时、切换时间源 | 直接显示正确时间，不翻页 |
| 校时、恢复窗口或长时间主线程阻塞后的大时间跳变 | 直接显示正确时间，不翻页 |
| 倒计时结束 | 直接落到 `00:00:00` 或 `00:00:00.000`，不做误导性的连续翻页 |

对于“正常连续变化”的判断，可把相邻渲染的时间差和显示模式一并纳入：只有符合时钟正常前进一秒、或倒计时正常递减一秒的变化才允许翻页。出现回跳、跳过多秒或源切换标记时直接更新。

## 性能

当前主界面已经以约 60fps 更新毫秒，因此翻页效果不能额外把每一帧都变成动画创建、布局测量或完整 DOM 重建。

推荐方案的性能约束：

- 毫秒继续用已有的高频文字更新；
- 仅在秒级变化时创建翻页动画；普通情况下每秒只触发一个数字，跨分钟或小时才短暂同时触发多个数字；
- 保持稳定的数字 DOM，逐位比较后只更新变化节点；
- 不在渲染循环中调用 `getBoundingClientRect()`；Mini 继续只在字符串长度改变时测量；
- 动画只修改 `transform` 和 `opacity`，避免布局型或高绘制成本属性；
- 默认不要使用 `will-change`。若实际设备出现卡顿，再只为正在翻转的单个位短暂添加，动画结束立即移除；
- 通过真实窗口而不是只看代码验证 CPU、掉帧、残影与窗口拖动。

MDN 的性能资料以 60fps、每帧约 `16.7ms` 为平滑动画参考。当前项目 `16ms` 的渲染节奏已接近这一帧预算；限定翻页到秒级变化是避免竞争帧预算的必要条件。

## 无障碍、交互与回退

### 无障碍和交互

- 不要给持续更新的时钟或倒计时增加 `aria-live`。否则读屏会按秒，甚至在毫秒模式下更频繁地打断用户；
- 逐位翻页 span 只承担视觉呈现，应设为 `aria-hidden="true"`；时间的语义仍由现有外层按钮或文本元素承担；
- 标准模式现有的精度切换点击、Tooltip 和键盘焦点不应因内部数字节点而改变；
- Mini 的内部数字节点不应成为 button，不应截获点击，也不应标为非拖动区域；这样能保留现有拖动与双击恢复标准模式；
- `.critical` 的缩放脉冲在父级，翻页 transform 在子级，避免两个动画争用同一个元素的 `transform` 属性；
- 动画不应新增可聚焦元素，不能覆盖 Mini 右侧操作按钮或扩张其命中区。

### 减少动态效果

翻页是装饰性而非功能性动效。用户系统表达“减少动态效果”偏好时，应完全直接替换数字，不执行翻页。

CSS 路径可使用：

```css
@media (prefers-reduced-motion: reduce) {
  .digit-flip {
    animation: none;
    transform: none;
  }
}
```

WAAPI 路径还需要在 JavaScript 中检查 `matchMedia("(prefers-reduced-motion: reduce)")`：

- 初始化时为 `reduce`：不创建动画；
- 运行中切换为 `reduce`：取消当前动画，后续直接替换；
- 静态显示不得影响时间精度、倒计时、最后五秒高亮或 Mini 宽度。

在 Windows 11 中，用户通常可在“设置 → 辅助功能 → 视觉效果 → 动画效果”关闭系统动画。

### WebView2 特性回退

项目使用 Evergreen WebView2，实际 web 平台能力取决于最终用户机器的 Runtime 版本，而不是 Cargo 里 Tauri/Wry 的版本。实现应在启动时做保守检测：

```js
const canAnimateDigits =
  typeof Element.prototype.animate === "function"
  && CSS.supports("transform", "rotateX(1deg)");
```

不支持 WAAPI、CSS 3D、或启用了减少动态效果时，直接沿用当前静态 `textContent` 显示。动画能力不可用不得影响任何计时、校时、倒计时、拖动和窗口控制功能。

## PoC 最小范围与验收

### 最小改动范围

若后续获得实现授权，PoC 应只修改：

- `src/renderer/index.html`：为主时间值容纳逐位的被动数字节点；
- `src/renderer/app.js`：增加字符串差异比较、逐位更新、动画条件和回退；
- `src/renderer/styles.css`：增加数字槽位、3D 翻页和减少动态效果样式；
- 对应前端测试：覆盖数字差异、动画边界和静态回退。

PoC 不应修改：

- `src-tauri/` 内的 Rust、权限或窗口命令；
- `src/tauri-bridge.js`；
- 时间源协议、校时逻辑、倒计时核心、置顶、托盘或全局快捷键；
- `localStorage` 数据格式；
- 依赖清单。

### 验收清单

1. 标准模式整数秒：等待秒数变化，确认只有变化的秒位翻页，冒号不动。
2. 标准模式三位毫秒：确认 `.mmm` 连续更新但不翻页；跨秒时只有秒位翻页。
3. 时钟在 `59 → 00`、`09 → 10`、`59:59 → 00:00` 进位时，确认所有变化位同步、无残影。
4. 倒计时在普通递减和跨分钟/小时变化时，确认数字正确，且结束直接归零。
5. 最后五秒高亮期间，确认高亮脉冲与翻页可同时存在，不闪烁、不丢色、不缩放异常。
6. 切换“显示整秒 / 显示毫秒”，确认数字槽位重建稳定，点击与 Tooltip 不回归。
7. Mini 的进入、退出、拖动、双击恢复标准模式和右侧三个操作按钮均不回归。
8. 三位及以上小时倒计时变化时，确认 Mini 仅在长度变化时调整一次宽度，数值始终单行。
9. 启用系统减少动态效果后，确认完全静态，但时钟、倒计时和高亮规则正确。
10. 最小化/隐藏再恢复、切换时间源、手动校时与主线程停顿恢复后，确认大时间跳变不会产生连续误导性翻页。
11. 在实际 Tauri/WebView2 窗口验收 CPU、拖动、Tooltip、焦点和残影；特性检测失败时应自动退化为当前静态显示。
