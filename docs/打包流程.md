# 打包流程

本文件是 Windows 打包的唯一操作规范。`npm run tauri:build` 是唯一正式入口；不要直接运行 `npx tauri build` 后手工复制文件，也不要让 `build.ps1` 反向调用该 npm 脚本。

## 版本

发布版本必须在以下三个文件中完全一致：

- `package.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`

版本变更应在同一个提交中完成。`build.ps1` 会在构建前检查一致性，不一致时立即失败。

## 目录职责

| 目录 | 用途 | 是否用于分发 |
| --- | --- | --- |
| `src-tauri/target/release` | Rust/Tauri 编译产物，包括 `floating-clock.exe` | 否 |
| `src-tauri/target/release/bundle/nsis` | Tauri 生成的 NSIS 中间安装包 | 否 |
| `src-tauri/target/release/bundle/wix` | 可能由历史 WiX 构建留下的中间产物 | 否 |
| `dist` | 经脚本复制并带版本号的最终文件 | 是 |

`target` 是构建缓存和中间产物，出现 `bundle/nsis` 或 `bundle/wix` 子目录属于正常情况。不要为了“整理输出”删除其中内容；需要清理构建缓存时先取得明确确认。

## 发布步骤

在仓库根目录执行：

```powershell
npm test
Set-Location src-tauri
cargo test
Set-Location ..
npm run tauri:build
```

最后核对 `dist/` 中存在当前版本的四个文件：

```text
FloatingClock-<version>-tauri-win-x64-setup.exe
FloatingClock-<version>-tauri-win-x64-setup.exe.sig
FloatingClock-<version>-tauri-win-x64.exe
latest.json
```

第一个是 NSIS 安装包，`.sig` 是 updater 签名，第二个 exe 是便携版，`latest.json` 是更新清单。构建脚本会在任一源产物缺失时失败，不会报告伪成功。

私钥必须存放在仓库之外并单独备份，不得提交、写入脚本或日志。默认位置为：

```powershell
$env:USERPROFILE\.tauri\floating-clock.key
```

首次在当前 Windows 用户下发布前，执行一次初始化。密码会由 Windows DPAPI 加密，只能由当前 Windows 用户在本机解密：

```powershell
$passwordFile = "$env:USERPROFILE\.tauri\floating-clock.password.dpapi"
$securePassword = Read-Host "Updater 签名密码" -AsSecureString
$securePassword | ConvertFrom-SecureString | Set-Content -LiteralPath $passwordFile
```

之后直接运行 `npm run tauri:build` 即可自动读取默认私钥和 DPAPI 密码文件。临时设置的 `TAURI_SIGNING_PRIVATE_KEY` 与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 环境变量仍具有优先级，便于 CI 或临时覆盖。DPAPI 文件不应复制到其他电脑；迁移设备后需在新设备上重新初始化。

创建 `v<version>` GitHub Release 后，上传上述四个文件。安装版从固定地址
`https://github.com/zionyang/floating-clock/releases/latest/download/latest.json`
检查更新；便携版不执行应用内安装。

## 维护约束

- `package.json` 的 `tauri:build` 脚本调用 `build.ps1`；`build.ps1` 必须直接调用 `node_modules/.bin/tauri.cmd build`，不能调用 `npm run tauri:build`。
- 新增打包器时，先更新本文档和 `src-tauri/tauri.conf.json`，再修改脚本和验收文件名。
- `dist/` 可以保留旧版本，避免误删已有分发件；发布时以文件名中的版本号区分。
- 更新私钥及 DPAPI 密码文件不得入库；私钥或密码丢失后，已有安装版将无法验证后续更新。
- `.claude/`、`target/`、`dist/` 等本地文件不应被无意提交。提交前用 `git status --short` 检查范围。
